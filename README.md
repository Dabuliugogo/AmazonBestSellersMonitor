# 亚马逊 BSR TOP100 店铺监控工具

> 纯本地运行 · 单文件 Python 主程序 + 内嵌本地 Web 界面 · 数据不出本机

监控亚马逊美国站指定品类的 Best Sellers（BSR）TOP100 榜单，围绕"目标店铺"完成 **上榜识别 → 榜单变动追踪 → AI 分析报告 → 运营销售建议** 的闭环，全部数据只写入本机 `data/` 目录。

技术选型对比、系统架构与数据流详见 [docs/技术选型与架构方案.md](docs/技术选型与架构方案.md)。

---

## 一、这个工具能做什么

| 能力 | 说明 |
|---|---|
| TOP100 抓取 | 浏览器滚动可抓满 100 款（rank 连续）；未装可选依赖时自动回退 HTTP 直抓（最多约 60 款） |
| 目标店铺上榜识别 | 按店铺名 / 关键词 / 店铺主页 marker 判定，汇总上榜商品（标题、ASIN、排名、价格、链接） |
| 榜单变动对比 | 相邻快照 ASIN 集合差：新上榜 / 落榜；支持任意两次历史快照回溯对比 |
| AI 分析报告 | 新上榜共性、落榜归因、市场画像；支持本地 Ollama / OpenAI 兼容 API / 离线模板 |
| 运营销售建议 | 规则引擎生成可落地建议，配置模型后可升级为 AI 增强版 |
| 导出 | 上榜明细 CSV、变动明细 CSV、运营建议 MD（统一写入 `data/exports/`） |

**当前监控对象（写在代码里的页面常量）**：亚马逊美国站 · Best Sellers > Electronics > Portable Bluetooth Speakers（`zgbs/electronics/172623`）第 1、2 页。价格按页面原样币种记录（当前为美元 `$`），不做任何汇率换算。如需更换站点/品类，修改 `bsr_monitor.py` 顶部的 `TOP100_PAGE_1` / `TOP100_PAGE_2` 两个常量即可。

## 二、环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（macOS / Linux 可运行同款 Python 脚本，界面一致） |
| Python | 3.10 或更高版本，安装时勾选 **Add python.exe to PATH** |
| 网络 | 能访问 `amazon.com`；网络受限时可在界面设置中填 HTTP 代理 |

## 三、快速开始（3 步）

1. **启动**：双击 `run.bat`。命令行窗口会显示服务地址，浏览器自动打开界面（默认 `http://127.0.0.1:8965`，端口被占用时会自动向后寻找可用端口，以窗口输出为准）。窗口不要关闭，关闭即退出工具。
   - `run.bat` 查找 Python 的顺序：① 本目录 `python_local.txt` 记录的解释器路径 → ② PATH 中的 `python` → ③ Windows `py` 启动器 → ④ 都没有则提示安装 Python。
   - `python_local.txt` 是**本机专属文件**（内容仅一行 Python 绝对路径），可选、可以不存在；仓库已通过 `.gitignore` 排除它，不会上传。
2. **配置目标店铺**：进入 ⑤ 设置 →「店铺设置」，填写店铺名称、店铺关键词（逗号分隔、小写匹配）、店铺主页 marker（可留空），点「保存店铺设置」。未配置时看板显示"未设置目标店铺"，不影响抓取。
3. **抓取**：点击顶部「立即抓取更新」，等待 20~60 秒。首次抓取作为基线快照，不做变动对比；第二次起自动出对比结果。

> 想抓满 100 款：先双击 `install_scroll_deps.bat`（等价 `python -m pip install playwright`，复用本机 Edge/Chrome，不下载浏览器内核）。

## 四、AI 模型配置（三选一）

在 ⑤ 设置 →「AI 模型配置」中选择模式，**默认模式为离线模板**（不调用任何模型）。

| 模式 | 配置方式 | 特点 |
|---|---|---|
| 离线模板（默认） | 不填任何 Key | AI 报告区按当前提示词 + 本次真实快照数据渲染模板化报告，运营建议走内置规则引擎，完全离线 |
| 本地 Ollama | 安装 Ollama 并 `ollama pull qwen2.5:7b`；模式选「本地 Ollama」，Base URL 默认 `http://127.0.0.1:11434/v1` | 全离线、免费，数据不出本机 |
| OpenAI 兼容 API | 模式选「OpenAI 兼容 API」，填 Base URL（如 `https://api.deepseek.com/v1`）、Model、API Key，点「测试连接」 | 配置最省心，按量计费 |

API Key 只保存在本机 `data/config.json`，不会上传。高级项：`max_tokens`（单次最大生成长度，默认 8192，0 = 交给服务端默认）、`num_ctx`（仅本地 Ollama 生效的上下文窗口，默认 16384）。

## 五、提示词设置（可编辑）

⑤ 设置 →「提示词设置」中可直接编辑「AI 分析报告提示词（`prompt_analysis`）」与「运营销售建议提示词（`prompt_advice`）」，点「保存提示词」立即生效，「恢复默认」一键还原内置预设；留空自动回退内置默认。

可用占位符：`{store_label}` `{gen_at}` `{fetch_at}` `{summary_json}` `{top_items}` `{store_items}` `{new_in}` `{dropped}` `{new_in_count}` `{dropped_count}` `{data_block}`。若提示词未包含任何数据占位符，生成时会自动在末尾追加完整真实数据块，确保模型有数据可分析。

## 六、界面功能对照（4 大区 + 设置）

| 标签页 | 内容 | 关键按钮 |
|---|---|---|
| ① 目标店铺上榜汇总 | 「TOP100 榜单整体画像」（价格档位分布固定五档 0-20 / 20-50 / 50-100 / 100-200 / >200、最低价/最高价/评论最多/评分最高、目标店铺上榜统计）+ TOP10 快速参考 + 目标店铺上榜商品明细 | 导出上榜CSV |
| ② 榜单变动对比 | "最近一次快照对比"（标注基准快照与本次快照）+「历史快照」表（点击两条记录可回溯任意两次对比，第 1 行为基准、第 2 行为目标） | 导出变动CSV |
| ③ AI 分析报告 | 报告全文；报告开头标注「报告生成时间 / 本次数据抓取时间 / 对比基准快照」，避免日期混用 | 顶部「生成 AI 分析」（用当前提示词基于最近快照重跑，不重新抓取、不覆盖其他区块） |
| ④ 运营销售建议 | 规则引擎版或 AI 增强版运营建议 | 顶部「生成运营建议(再跑一次AI)」；导出建议 MD |
| ⑤ 设置 | 店铺设置 / AI 模型配置 / 提示词设置 / 抓取与代理（定时间隔 ≥30 分钟、HTTP 代理、抓取模式）/ 本地数据 | 保存店铺设置、测试连接、保存配置、保存提示词、恢复默认、保存、打开数据目录 |

**变动口径说明**：② 区只统计相对基准快照的 **ASIN 集合差**（新进入榜单 / 跌出榜单），**不涉及 TOP100 内部商品的排名升降**。

## 七、抓取模式与"滚动抓满 TOP100"

亚马逊榜单页每页只服务端渲染约 30 款，HTTP 直抓存在数量上限（约 60 款）。⑤ 设置 →「抓取与代理」的「抓取模式」提供三档：

| 模式 | 行为 |
|---|---|
| 自动（推荐，默认） | 优先用本机 Edge/Chrome 滚动抓取；未装依赖 / 被拦截 / 失败时自动回退 HTTP 直抓，并在结果横幅提示原因 |
| 浏览器滚动 | 强制滚动抓取，两页各加载至约 50 卡，合计抓满 100 款、rank 连续 |
| HTTP 直抓 | 不启动浏览器，速度最快，最多约 60 款 |

未抓满 100 款时，结果上方会显示实际数量与原因，画像与对比均基于已获取部分。被 AWS WAF 人机验证拦截时，「自动」模式下 30 分钟内不再反复尝试滚动，直接改走 HTTP 直抓。

> 版本库中不包含 `data/config.json`、`python_local.txt` 及全部运行时数据。**下载本仓库后首次运行无需任何配置文件**：程序以内置默认配置启动（离线模板模式），在界面点「保存」后才生成 `data/config.json`。

### data 目录与配置文件说明

- `data/` 目录及其子目录（`snapshots/`、`changes/`、`reports/`、`exports/`、`raw/`）由**程序首次运行时自动创建**，无需手工准备，也不随仓库分发。
- `data/config.json` 是唯一的配置文件：仓库中不包含它；程序启动时若该文件缺失，会直接使用内置默认值运行（离线模板模式），**不会自动写盘**；只有在界面 ⑤ 设置中修改并点「保存」后才会生成。
- 配置在界面 ⑤ 设置页完成，共四块：**店铺设置**（店铺名称 / 关键词 / 主页 marker）、**AI 模型配置**（模式 `ai_mode`、Base URL、模型、API Key、`max_tokens`、`num_ctx`）、**提示词设置**（`prompt_analysis`、`prompt_advice`）、**抓取与代理**（定时间隔 `schedule_minutes`、`http_proxy` / `https_proxy`、抓取模式 `fetch_mode` 等）。
- 该文件可能包含店铺信息与 API Key，已被 `.gitignore` 排除，请勿提交或随文件夹分发。

## 九、常见问题

| 问题 | 处理 |
|---|---|
| 提示"疑似触发反爬 / 需要验证码" | 等 10~30 分钟再试；或到 ⑤ 设置填 HTTP 代理；避免高频点击（手动抓取有 60 秒冷却） |
| 提示"页面结构可能变化或榜单内容不足…原始 HTML 已保存到 data/raw/…" | 本次仅解析到不足 60 款商品；可将 `data/raw/` 下最新 html 文件交给维护者适配解析规则 |
| 抓取成功但目标店铺为 0 | 到 ⑤ 设置 →「店铺设置」确认店铺名称 / 关键词 / 主页 marker 已保存；商品卡必须渲染店铺信息（如 "Visit the XXX Store"）才会被识别，个别卡片无店铺信息属正常漏判，可人工核对链接 |
| 第一次抓取没有"变动对比" | 正常。首次快照作为基线，第二次抓取起才有 diff |
| 浏览器没有自动打开 | 手动访问命令行窗口显示的地址（默认 `http://127.0.0.1:8965`） |
| 端口被占用 | 工具会自动尝试后续端口，以命令行输出为准 |
| 导出 CSV 用 Excel 打开中文乱码 | 已按 UTF-8 BOM（`utf-8-sig`）写入，正常不应乱码；若仍乱码请用 WPS / 记事本打开 |
| 想看某个历史时点的数据 | ② 区「历史快照」表点击两条记录即可回溯对比 |

## 十、数据与隐私
