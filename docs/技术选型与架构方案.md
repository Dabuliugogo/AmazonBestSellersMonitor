## 一、技术形态选型对比

| 维度 | A. HTML 单文件 | B. Python 脚本 + 本地服务 + 浏览器界面（推荐） | C. Python + PyWebView 桌面程序 | D. Electron 单包 exe |
|---|---|---|---|---|
| 数据源抓取（跨域） | 致命伤：浏览器 fetch 直连 amazon.com 被 CORS 拦截，只能依赖第三方公共代理（泄露数据、不稳定、反爬更严） | 本地 Python 发 HTTP 请求，无 CORS；可带 UA/Cookie/代理/退避策略 | 同左，pywebview 仅作窗口壳 | 同左 |
| 本地存储 | 仅 localStorage/IndexedDB，无法按"快照文件"管理，导出体验差 | 原生文件系统：snapshots/、changes/、reports/ 目录清晰 | 同左 | 同左 |
| 大模型接入 | 跨域 + CORS 同样受限，无法稳定对接 Ollama 之外的方案 | 可调 Ollama(127.0.0.1) / 任意 OpenAI 兼容 API | 同左 | 同左 |
| 开箱即用门槛 | 双击即用 | 需安装 Python（提供 run.bat 一键启动；可再打包 exe 免安装） | 需安装 Python + pywebview，依赖多于 B | 打包后免安装，但安装包体积大，需 Node/打包工具链 |
| 定时抓取 | 页面开着才有效 | 进程内定时器 + 可挂 Windows 计划任务 | 同左 | 同左 |
| 二次开发/排障 | 易，但功能上限低 | 中 | 中 | 低（改一行要重新打包） |
| 维护成本 | 低 | 低（标准库为主） | 中 | 高 |

**结论：推荐 B 方案 —— Python 单文件主程序（标准库为主）+ 内嵌本地 HTTP 服务 + 自动打开浏览器操作界面。**
理由：
1. HTML 单文件在"跨域抓取"这个硬需求上直接出局；
2. B 比 C 少一层 pywebview 依赖，故障面更小，且浏览器界面开发调试友好；
3. 若用户完全没有 Python，可执行 `build_exe.bat` 打包成免安装 exe（打包与分发说明见根目录 [README.md](../README.md)），此时体验等同 D，但包体小得多。

> 打包后仍是"别人下载解压 → 双击 → 浏览器自动打开"的零门槛形态，符合交付目标。

### 抓取引擎（两种执行路径，抓取模式三档切换）

| 抓取模式（`fetch_mode`） | 执行路径 | 结果上限 |
|---|---|---|
| `auto`（默认，推荐） | 优先浏览器滚动抓取，未装依赖 / 被拦截 / 失败时自动回退 HTTP 直抓并在横幅提示原因 | 正常可抓满 100 |
| `scroll` | 强制浏览器滚动：复用本机 Edge/Chrome 打开两页榜单并向下滚动触发懒加载（每页约 50 卡），rank 连续 | 100 |
| `http` | 纯 HTTP 请求（不启动浏览器），gzip 解压 + 正则/HTMLParser 解析 | 约 60 |

### 数据流（一次"立即抓取更新"）

1. 前端点击 → `POST /api/fetch`
2. 抓取引擎带随机浏览器 UA（12 组轮换）+ Cookie，先访问 amazon.com 首页取 Cookie，再依次请求 `pg=1`、`pg=2`（HTTP 直抓时两页之间随机 6~14 秒延时）
3. HTML 解析器逐商品卡提取：排名(badge)/ASIN/标题/价格(含币种与价格形态)/星级/评论数/店铺链接/店铺名
4. **数量校验**：解析条数少于 60 视为失败，把原始 HTML 写入 `data/raw/page_failed_<时间戳>.html`，界面提示页面结构可能变化（避免静默出空数据）
5. 将本次 TOP100 保存为新快照（`snapshots/top100_<时间戳>.json` + 更新 `latest.json` + 追加 `history.json`）
6. 与基准快照对比：**ASIN 集合差** → 新上榜 / 落榜 → 写入 `changes/`（json + csv）
7. 生成报告：`reports/ai_analysis_<时间戳>.md`（AI 分析）与 `reports/advice_<时间戳>.md`（运营建议）；配置模型时调用模型（失败自动降级为真实数据模板总结），未配置模型时直接走模板 + 规则引擎
8. 前端刷新四大区，用户可一键导出 CSV / MD

### 报告重跑入口（不重新抓取）

| 入口 | 接口 | 行为 |
|---|---|---|
| 顶部「生成 AI 分析」 | `POST /api/regenerate_analysis` | 读取最近快照，用当前生效提示词重新生成 AI 分析报告；不重新抓取页面、不覆盖抓取结果与其他区块 |
| 顶部「生成运营建议(再跑一次AI)」 | `POST /api/regenerate_advice` | 基于最近快照重新生成 AI 分析报告 + 运营建议 |
| ② 区历史快照 | `GET /api/compare?base=&target=` | 回溯任意两次快照的对比结果 |

### 报告时间标注

AI 分析报告正文开头固定输出：

> 报告生成时间：… ｜ 本次数据抓取时间：… ｜ 对比基准快照：…

内置默认提示词亦强制要求「引用日期只能使用快照抓取时刻所在日期」，避免把报告生成时刻误当成数据时刻。

### 定时抓取

- 界面可设置定时抓取（默认关闭，`schedule_minutes=0`），运行期间由进程内线程按间隔执行；间隔下限 30 分钟（反爬友好），建议 60~120 分钟
- 关闭窗口/进程即停止；如需开机长期自动运行，可挂 Windows 任务计划程序（见根目录 README）
- 手动刷新有 60 秒冷却（`fetch_cooldown_seconds`），避免高频请求

## 三、数据存储设计（全部本地文件）

```
data/
├── config.json               # 店铺名称/关键词/marker、AI 模式与模型、提示词、抓取与代理设置
├── latest.json               # 最近一次快照（供对比与展示）
├── history.json              # 快照索引：[{id, fetched_at, count, store_count, new_n, dropped_n}]
├── snapshots/
│   └── top100_<时间戳>.json   # 每次抓取的 TOP100 全量（含字段与抓取时间）
├── changes/
│   ├── diff_<时间戳>.json     # 本次对比：新上榜/落榜完整商品信息
│   └── diff_<时间戳>.csv
├── reports/
│   ├── ai_analysis_<时间戳>.md   # AI 榜单变动分析报告
│   └── advice_<时间戳>.md        # 运营销售建议报告
├── exports/                  # 用户点击导出生成的文件（上榜 CSV / 变动 CSV / 建议 MD）
└── raw/                      # 抓取异常时的原始 HTML 留档
```

`config.json` 主要字段：`store_name` / `store_keywords` / `store_id` / `store_page_marker`（店铺判定）、`ai_mode`（`offline`｜`ollama`｜`apikey`）/ `ai_base_url` / `ai_model` / `ai_api_key` / `ai_max_tokens` / `ai_num_ctx`、`prompt_analysis` / `prompt_advice`（可编辑提示词）、`http_proxy` / `https_proxy`、`fetch_cooldown_seconds` / `schedule_minutes` / `min_schedule_minutes` / `fetch_mode`、滚动抓取硬超时护栏 `scroll_page_timeout_sec`(75) / `scroll_overall_timeout_sec`(200)。

- 配置文件缺失时，程序以内置默认值在内存中运行（默认 `ai_mode=offline`），**不会自动写盘**；在界面点「保存」后才生成 `config.json`
- 快照比对默认取 `snapshots/` 中时间最近的前一份；② 区历史列表可回溯任意两次对比
- 数据只在本地读写，无任何上传

## 四、AI 模型接入方案对比

| 方案 | 门槛 | 成本 | 质量 | 离线 | 适配度 |
|---|---|---|---|---|---|
| ① 本地 Ollama（推荐给有 8GB+ 内存、可装 Ollama 的用户） | 中：需安装 Ollama 并拉取模型（如 qwen2.5:7b ~4.7GB） | 免费 | 中上，中文可用，7B 模型足够做业务归纳 | 全离线 | 可远程帮装一次，之后永久免费免 Key |
| ② 用户自填 OpenAI 兼容 API Key（OpenAI/DeepSeek/智谱等，base_url 可配置） | 低：粘贴 base_url + model + key 即可 | 按量计费（通常一次分析几美分） | 高 | 需联网 | 对大多数销售顾问最省心；Key 只存在本机 config.json，不上传 |
| ③ 内置离线模板 + 可编辑提示词（零模型，默认模式） | 最低：不填任何 Key；在 ⑤ 设置 →「提示词设置」查看/编辑提示词 | 免费/自选 | 取决于所填提示词与外部 AI | 完全离线 | 无模型也能跑通全流程；提示词可自定义并一键恢复默认，也可复制到任意外部 AI 使用 |

**实现约定**：工具内部统一走 OpenAI 兼容协议 `POST {base_url}/chat/completions`，因此 Ollama 的 `http://127.0.0.1:11434/v1` 与 OpenAI/DeepSeek 的地址可以同一套代码打通，切换模式只改配置。离线模式下点击顶部「生成 AI 分析」同样可用：报告按当前提示词 + 本次真实快照数据渲染（不调用模型），运营建议自动使用内置规则引擎。

## 五、防反爬与数据源处理策略

1. **低频**：手动抓取 60 秒冷却；定时抓取下限 30 分钟；HTTP 直抓两页之间随机 6~14 秒延时，并带随机退避重试
2. **浏览器化请求头**：随机轮换 12 组现代 Chrome/Edge/Firefox/Safari UA + Accept-Language + sec-ch-ua 等头
3. **Cookie 预热**：首次请求 amazon.com 首页获得 Cookie 后再访问榜单页，降低 Robot Check 概率
4. **验证码/拦截识别**：检测 `captcha`、`Robot Check`、`validateCaptcha`、`api-services-support@amazon.com` 等特征串，明确提示"疑似触发反爬，请等待 10-30 分钟或更换网络/配置代理"，绝不盲目重试；滚动抓取被 WAF 拦截后 30 分钟内不再反复尝试
5. **可选代理**：config.json 支持 `http_proxy`/`https_proxy`，供需要走代理访问美亚的用户使用
6. **页面结构兜底**：解析条数 < 60 或滚动未达预期时保留原始 HTML 到 `data/raw/`，并在界面给出明确错误信息，避免静默出空数据
7. **合规边界**：只抓公开 BSR 榜单页，不做账号登录、不抓需要登录的数据、不写自动下单/跟卖等违规功能；请勿高并发抓取

## 六、BSR 榜单局限性与使用提醒（工具内置提示也需向使用者说明）

1. **BSR 是销量相对排名，不是搜索排名**：TOP100 = 该品类近期（小时级滑动窗口）销量前 100，不等于自然搜索结果或广告位表现
2. **榜单小时级刷新、随时波动**：早晚两次抓取看到的榜单可能不同，单次快照只能代表抓取时刻；建议连续多日固定时间抓取形成趋势
3. **榜单变动口径**：② 区只统计相对基准快照的 **ASIN 集合差**（新进入榜单 / 跌出榜单），**不涉及 TOP100 内部商品的排名升降**
4. **店铺归属判定依赖商品卡内"Visit the X Store"信息**：部分自营/VC 商品或卡片未渲染店铺名的商品无法判归属；若某目标店铺商品未显示店铺链接会漏判（界面会展示"店铺可识别商品数/总榜数"供参考）
5. **榜单卡字段精度**：评论数/星级在卡片上可能被省略或延迟，解析不到的字段显示"—"属正常
6. **价格口径与档位**：价格按页面原样币种落库与展示（当前美站为美元 `$`，页面渲染 `$` 标价），**不做任何汇率换算**，展示时以币种代码（USD/CNY）标注；画像中的价格档位分布为**固定五档 0~20 / 20~50 / 50~100 / 100~200 / >200**（档位边界数值固定不变）。价格为卡片标价，不含 Coupon/Deal 折后价
7. **网络环境**：国内网络访问 amazon.com 可能不稳定或被要求验证码，必要时在设置中填代理；工具对 403/503/验证码做了识别与提示
8. **抓取数量**：HTTP 直抓受页面懒加载限制，最多约 60 款；需要完整 TOP100 请安装 playwright 依赖并使用「自动」或「浏览器滚动」模式
